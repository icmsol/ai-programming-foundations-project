# California State Procurement Opportunity Landscape

This project creates a reproducible Python data workflow for California Cal eProcure proposal-request data. It combines one year of completed solicitations with a July 24, 2026 snapshot of currently open solicitations, validates data quality, explores procurement activity, creates three labeled visualizations, and produces a conservative ICM Solutions opportunity-review table.

## What Was Built

- Reproducible ingestion of the original Cal eProcure HTML-table exports
- Reusable data-cleaning and deadline-feature functions
- A documented exploratory-analysis function
- Three labeled Matplotlib visualizations with written interpretations
- A processed combined CSV
- A conservative current-opportunity screen for manual ICM review

## Dataset

Primary data source: California Cal eProcure Event Search  
https://caleprocure.ca.gov/pages/Events-BS3/event-search.aspx

Data snapshot downloaded July 24, 2026.


Source: California State Contracts Register through Cal eProcure  
Official information: https://www.dgs.ca.gov/PD/Resources/Page-Content/Procurement-Division-Resources-List-Folder/Cal-eProcure-Portal-to-Access-Bid-Opportunities

Files included in `data/raw/`:

- `California Closed Proposal Requests in Last Year.xls`
- `California Current Open Proposal Requests.xls`

Although the files use an `.xls` extension, they are HTML-table exports and are loaded with `pandas.read_html()`.

## How to Run the Project

1. Clone the repository and enter the project folder.
2. Create and activate a Python virtual environment.
3. Install dependencies:

```bash
python3 -m pip install -r requirements.txt
```

4. Start Jupyter:

```bash
python3 -m jupyter notebook
```

5. Open `data_workflow.ipynb`.
6. Select **Kernel > Restart Kernel and Run All Cells**.
7. Confirm the notebook finishes without a traceback and recreates:
   - `data/processed/caleprocure_bids_combined.csv`
   - Three PNG files in `figures/`

## Reproducibility

The notebook uses relative file paths and retains the original raw exports. The processed CSV and figures are generated by the notebook rather than manually edited. Before final submission, regenerate the dependency file from the activated project environment:

```bash
python3 -m pip freeze > requirements.txt
```

A reviewer can then recreate the environment with:

```bash
python3 -m pip install -r requirements.txt
```

## Bias and Data-Quality Reflection

Poor cleaning could introduce bias by removing solicitations with missing buyer contacts, incorrectly treating Event ID as globally unique, or interpreting text-encoding artifacts as meaningful content. This workflow retains records with missing contacts, uses a composite record key, preserves original deadline text, and labels keyword matching as a manual-review aid. The data also overrepresents transportation and facilities procurement, so statewide volume should not be treated as a direct measure of ICM’s addressable IT-consulting market.

## Future Machine-Learning Workflow

A future model would require outcome labels such as pursued, submitted, shortlisted, or won. It would also need full solicitation text, contract-value or effort data, procurement-vehicle information, and carefully separated training, validation, and test records.

## Neural-Network Preparation

A neural-network approach would require consistent document collection, text extraction, de-duplication, labeling, and handling of class imbalance. The short event titles in the current exports are not sufficient for a reliable deep-learning classifier.

## Agentic Automation Potential

A future agent could retrieve new listings, screen and summarize possible matches, identify missing qualification information, and place results into a human-review queue. It should not autonomously make bid/no-bid decisions, contact buyers, or submit proposals.
